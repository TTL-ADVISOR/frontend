# 디자인 규칙

화면을 새로 만들거나 고칠 때 따르는 규칙입니다. 방향은 흰 배경과 따뜻한 회색, 브랜드 빨강, 굵은 산세리프, 모노 데이터, 얇은 구분선입니다.

## 색

방향: 따뜻한 회색 한 가족 + 브랜드 빨강 하나. 빨강과 온도가 같은 회색을 써서 화면 전체가 한 색 계열로 보이게 합니다.

| 역할 | 값 | 어디에 |
|---|---|---|
| 회색 | `--gray-0`~`--gray-950` (OKLCH 색상각 45°, 채도 0.003~0.01). 글자 `#1f1b19`, 보조 글자 `#78716e`, 구분선 `#e5e1df`, 입력칸 테두리 `#918b88` | 글자, 구분선, 옅은 바탕(`#fcfaf9`, `#f8f5f4`) |
| 먹색 | `#14110f`, `#1f1b19` | 결과 예시 창, 코드 블록, 알림, 바닥글, 로그인 오른쪽 면. **남색을 쓰지 않습니다** |
| 빨강 | `#e5121b` (`--red-600`), 누를 때 `#c4000d`, 먹색 위 `#ff3b42`, 옅은 면 `#fff1ef` | 로고, 주요 버튼(한 화면에 하나), 지금 위치(사이드바 아이콘, 고른 탭 밑줄, 지금 할 단계 번호), 추천 결과 |
| 앰버 | 글자 `#9a5505`, 바탕 `#fff1da`, 테두리 `#edcc95`, 먹색 위 `#f7b83d` | 경고, staleness 초과, 빠진 필드, 읽지 못한 줄, 캐시 비우기 = **주의** |
| 초록 | `#2b7440`, 바탕 `#e8f3e9` | 완료 배지, hit 같은 좋은 결과 |
| 오류 | `#a92321`, 바탕 `#fef0ee`, 테두리 `#f6c3bc` | 파싱 실패, 요청 실패. **항상 아이콘·문장·바탕과 함께**. 삭제 버튼은 채운 빨강이 아니라 테두리만 |

- 예전 문제: 남색(slate)·보라 회색(zinc)·순회색이 섞여 있었고, 차가운 남색 위에 따뜻한 빨강을 올려 색이 떨려 보였습니다(색입체시). 회색을 한 가족으로 바꾸고 어두운 면을 먹색으로 바꿨습니다.
- 주요 버튼이 빨강이라 오류와 헷갈리지 않게, 오류는 아이콘과 옅은 바탕으로, 삭제는 테두리 버튼으로 구분합니다.
- 고른 항목(업로드 이력 등)은 빨간 면이 오류처럼 보여서 회색 면 + 진한 테두리로 표시합니다.
- 색은 CSS 변수로만 씁니다. 화면 코드에 hex를 직접 쓰지 않습니다(흰색 `#fff` 제외).
- 모든 글자는 바탕 대비 4.5:1 이상입니다. 옅은 바탕(`#f8f5f4`) 위 보조 글자는 `#5c5552`를 씁니다.
- 그라데이션, 장식 그림자, 장식 그림은 쓰지 않습니다. 그림자는 결과 예시 창, 펼친 사이드바, 알림에만 씁니다.

## 글자

| 용도 | 글꼴 | 크기 |
|---|---|---|
| 본문 | Pretendard Variable (jsDelivr, 쓰는 글자만 받는 판) | 16px |
| 보조 | 산세리프, 회색 | 14px |
| 데이터 | 모노 | 13~14px |
| 화면 제목 | 700 | 28px |

- 경로, 패턴, JSON은 항상 모노로 씁니다.
- 숫자 열은 오른쪽으로 정렬하고 `font-variant-numeric: tabular-nums`를 씁니다.
- 굵은 이탤릭은 로고 글자에만 씁니다.

## 레이아웃

- 카드 상자를 늘어놓지 않습니다. 목록과 단계는 구분선으로 나눕니다.
- 장식용 아이콘은 쓰지 않습니다. 아이콘은 사이드바 메뉴처럼 기능이 있는 곳에만 쓰고, `components/Icon.tsx`의 선 아이콘만 씁니다.
- 같은 버튼과 문구를 한 화면에서 반복하지 않습니다. 같은 예시도 여러 곳에 되풀이하지 않습니다.
- 앱 화면은 맨 위에 화면 머리(위치 표시, 제목, 설명)를 두고 아래 구분선으로 내용과 나눕니다 (`.page-head`).
- 소개 화면 순서: 첫 화면(제목 + 결과 화면 예시 창) → 동작 방식(2×2) → 연동(로그 형식과 설정 예시를 나란히) → 질문 → 먹색 바닥글.
- 로그인·회원가입: 왼쪽 폼, 오른쪽 먹색 면에 추천 기준 문구와 예시 수치 3개(평균 예상 히트율, 평균 오래된 응답, 캐시를 추천한 엔드포인트 수), 아래에 빨간 로고. 수치는 소개 화면 예시 결과에서 계산해 두 화면이 어긋나지 않게 합니다. 면 전체를 빨강으로 칠하면 너무 강해서 빨강은 로고에만 씁니다. 서비스 소개 문장은 폼 위 부제목에만 두고, 오른쪽에는 부제목에 없는 내용만 둡니다.

## 공통 부품

- **탭** (`components/Tabs.tsx`): 글자와 밑줄만 씁니다. 선택된 탭은 진한 글자와 빨간 밑줄입니다. 화살표·Home·End로 옮깁니다.
- **코드 블록** (`components/CodeBlock.tsx`): 먹색 바탕, 오른쪽 위 복사 버튼.
- **알림** (`features/toast`): 오른쪽 아래 먹색 띠(완료는 초록 점, 경고는 앰버 점), 5초 뒤 사라짐. 방금 한 작업의 결과(업로드 처리 끝)에만 씁니다. 화면에 이미 보이는 오류를 알림으로 또 띄우지 않습니다.
- **불러오는 중**: 표는 `SkeletonRows`로 빈 줄을 보여 줍니다.
- **위치 표시**: `프로젝트 / 프로젝트 이름 / 하위 화면`. 맨 끝은 링크가 아닙니다.
- **프로젝트 워크스페이스**: 사이드바 메뉴 개요 · 로그 · 정책 · 분석 · 설정. 정책·분석은 API가 생기기 전까지 "준비 중"으로 둡니다.
  - 개요: 로그가 없으면 숫자 대신 3단계 시작 안내. 로그가 있으면 "다음 할 일" 한 줄 + 요약 숫자 한 줄(상자 없이 세로 구분선) + 최근 업로드 표.
  - 설정: 프로젝트 이름을 그대로 입력해야 삭제 버튼이 켜집니다.
- **요약 숫자**: 28px / 600. 분석이 없는 값은 0으로 채우지 않고 아예 보여 주지 않습니다.
- **분석 결과 문구**: 확정 대신 추정임을 드러냅니다. "예상 히트율", "관측된 변경 주기"처럼 씁니다.
- **목록**: 카드 대신 표를 씁니다. 검색·정렬은 표 위에 둡니다. 표 머리는 옅은 띠, 행은 48px(목록 52px), 숫자는 오른쪽 정렬입니다.
- **사이드바**: 옅은 회색 바탕. 지금 위치는 흰 면 + 빨간 아이콘 + 굵은 글씨, 마우스를 올린 메뉴는 회색 면으로 서로 다르게 보입니다.

## 앞으로 만들 화면 (메모)

분석 API가 생기면 아래 구조로 만듭니다.

- **프로젝트 상세**
  - 위쪽: 프로젝트 이름, 마지막 분석 시각, [분석 실행] 버튼. 파싱 중이거나 로그가 없으면 버튼을 끄고 이유를 보여 줍니다.
  - 탭: 결과 | 로그 | 정책
  - 결과가 없을 때: 탭 대신 단계를 보여 줍니다. ① 로그 업로드 → ② 정책 설정(선택) → ③ 분석 실행
  - 분석 뒤에 로그나 정책이 바뀌었으면 앰버 배너를 띄웁니다. "설정이 바뀌었어요. 다시 분석하세요"
- **정책 탭**: 표로 바로 편집합니다. 열은 패턴(모노), 허용 staleness(초), 매칭 요청 수, 자동/커스텀, 삭제입니다. 패턴마다 매칭되는 예시 경로 3개를 보여 줍니다.
- **결과**
  - 요약 숫자 4개: 엔드포인트 수, 캐시 추천 수, 전체 예상 히트율, 데이터 부족 수. 분석 기간과 총 요청 수도 함께 보여 줍니다.
  - 엔드포인트 표
    - 열: 엔드포인트, 판정, 추천 TTL, 예상 히트율(작은 막대), 오래된 응답, 요청 수, 쓰기 비율
    - 기본 정렬은 요청 수 내림차순입니다.
    - 추천 TTL 숫자만 빨강으로 씁니다. 초와 사람이 읽는 단위를 함께 씁니다.
  - 행을 누르면 오른쪽 서랍이 열립니다.
    - TTL별 곡선: 소개 화면 차트와 같은 형태이고, 추천 점만 빨강입니다.
    - 판정 이유 한 줄
    - 설정 복사: Redis `EXPIRE`, Spring `RedisCacheConfiguration.entryTtl`, `Cache-Control: max-age`
- **프로젝트 목록**: 분석 API가 생기면 엔드포인트 수, 예상 히트율, 마지막 분석 시각 열과 "최근 분석순" 정렬을 더합니다.
- **소개 화면**: 샘플 로그(B12)와 분석(B9~B11)이 생기면 "샘플 로그로 체험"과, 샘플 로그로 실제 계산한 Before/After("전부 60초" 대 추천)를 넣습니다.
