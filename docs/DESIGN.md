# 디자인 규칙

화면을 새로 만들거나 고칠 때 따르는 규칙입니다. 방향은 흰 배경, 굵은 산세리프, 모노 데이터, 얇은 구분선입니다.

## 색

| 역할 | 값 | 비율 |
|---|---|---|
| 바탕 | 흰색 `#ffffff` | 약 60% |
| 글자·구분선·어두운 구간 | 차콜 `#1c1c1e`, 회색 `#71717a` `#5f6b7a` | 약 30% |
| 브랜드 빨강 | `#e5121b` (`--color-brand`) | 10% 이하 |
| 경고 | 앰버 글자 `#b45309`, 바탕 `#fef3c7` (`--color-warning*`) | 필요할 때만 |

**빨강은 "이 숫자를 쓰세요"라는 뜻으로만 씁니다.**

- 빨강은 로고와 추천 결과에만 씁니다. 추천 결과는 추천 TTL 숫자, 그래프의 추천 점, "캐시 추천" 판정입니다. 화면당 1~2곳이면 충분합니다.
- 단계 번호, 현재 메뉴 표시, 드래그 중 테두리 같은 장식에는 차콜이나 회색을 씁니다.
- 경고와 위험은 앰버 글자로 씁니다. 파싱 실패, staleness 초과, 쓰기 과다가 여기에 해당합니다.
  - 그래프에서 기준을 넘는 구간은 회색 빗금으로 칠하고, 라벨만 앰버로 씁니다.
  - `#d97706`은 흰 바탕에서 대비가 3.2:1이라 글자에 쓰지 않습니다. 글자는 `#b45309`를 씁니다.
- 이벤트("비움" 같은 것)는 굵은 차콜 글자로 씁니다.
- 주 버튼은 차콜로 채웁니다. 빨강 버튼은 쓰지 않습니다.
- 삭제 같은 위험한 동작은 테두리나 글자를 `--color-danger`로 쓰고, 확인 단계를 붙입니다.
- 어두운 바탕(`#1c1c1e`)에서는 `#e5121b`의 대비가 3.6:1입니다. 그래서 밝힌 빨강 `#ff3b42`를 쓰고, 큰 숫자나 그래픽에만 씁니다.
- 그라데이션과 장식용 그림자는 쓰지 않습니다. 구간은 배경색과 구분선으로 나눕니다.

## 글자

| 용도 | 글꼴 | 크기 |
|---|---|---|
| 본문 | 산세리프 | 16px |
| 보조 | 산세리프, 회색 | 14px |
| 데이터 | 모노 | 13~14px |

- 경로, 패턴, JSON은 항상 모노로 씁니다.
- 숫자 열은 오른쪽으로 정렬하고 `font-variant-numeric: tabular-nums`를 씁니다.
- 굵은 이탤릭은 로고 글자에만 씁니다.

## 레이아웃

- 카드 상자를 늘어놓지 않습니다. 목록과 단계는 구분선으로 나눕니다.
- 장식용 아이콘은 쓰지 않습니다. 아이콘은 사이드바 메뉴처럼 기능이 있는 곳에만 쓰고, `components/Icon.tsx`의 선 아이콘만 씁니다.
- 같은 버튼과 문구를 한 화면에서 반복하지 않습니다.

## 공통 부품

- **탭** (`components/Tabs.tsx`): 글자와 밑줄만 씁니다. 화살표·Home·End로 옮깁니다.
- **코드 블록** (`components/CodeBlock.tsx`): 차콜 바탕, 오른쪽 위 복사 버튼.
- **알림** (`features/toast`): 오른쪽 아래 차콜 띠, 5초 뒤 사라짐. 방금 한 작업의 결과(업로드 처리 끝)에만 씁니다. 화면에 이미 보이는 오류를 알림으로 또 띄우지 않습니다.
- **불러오는 중**: 표는 `SkeletonRows`로 빈 줄을 보여 줍니다.
- **위치 표시**: `프로젝트 / 프로젝트 이름`. 맨 끝은 링크가 아닙니다.
- **목록**: 카드 대신 표를 씁니다. 검색·정렬은 표 위에 둡니다.

## 앞으로 만들 화면 (메모)

분석 API가 생기면 아래 구조로 만듭니다.

- **프로젝트 상세**
  - 위쪽: 프로젝트 이름, 마지막 분석 시각, [분석 실행] 버튼. 파싱 중이거나 로그가 없으면 버튼을 끄고 이유를 보여 줍니다.
  - 탭: 결과 | 로그 | 정책
  - 결과가 없을 때: 탭 대신 단계를 보여 줍니다. ① 로그 업로드 → ② 정책 설정(선택) → ③ 분석 실행
  - 분석 뒤에 로그나 정책이 바뀌었으면 앰버 배너를 띄웁니다. "설정이 바뀌었어요. 다시 분석하세요"
- **정책 탭**: 표로 바로 편집합니다. 열은 패턴(모노), 허용 staleness(초), 매칭 요청 수, 자동/커스텀, 삭제입니다. 패턴마다 매칭되는 예시 경로 3개를 보여 줍니다.
- **결과**
  - 요약 숫자 4개: 엔드포인트 수, 캐시 추천 수, 전체 예상 히트율, 데이터 부족 수. 분석 기간과 총 요청 수도 함께 보여 줍니다.
  - 엔드포인트 표
    - 열: 엔드포인트, 판정, 추천 TTL, 예상 히트율(작은 막대), 오래된 응답, 요청 수, 쓰기 비율
    - 기본 정렬은 요청 수 내림차순입니다.
    - 추천 TTL 숫자만 빨강으로 씁니다. 초와 사람이 읽는 단위를 함께 씁니다.
  - 행을 누르면 오른쪽 서랍이 열립니다.
    - TTL별 곡선: 소개 화면 차트와 같은 형태이고, 추천 점만 빨강입니다.
    - 판정 이유 한 줄
    - 설정 복사: Redis `EXPIRE`, Spring `RedisCacheConfiguration.entryTtl`, `Cache-Control: max-age`
- **프로젝트 목록**: 분석 API가 생기면 엔드포인트 수, 예상 히트율, 마지막 분석 시각 열과 "최근 분석순" 정렬을 더합니다.
- **소개 화면**: 샘플 로그(B12)와 분석(B9~B11)이 생기면 "샘플 로그로 체험"과, 샘플 로그로 실제 계산한 Before/After("전부 60초" 대 추천)를 넣습니다.
