# 디자인 규칙

화면을 새로 만들거나 고칠 때 따르는 규칙입니다. 방향은 흰 배경, 굵은 산세리프, 모노 데이터, 얇은 구분선입니다.

## 색

방향: Vercel의 여백·얇은 선, Supabase의 표·사이드바, Linear의 정보 밀도. 브랜드 개성은 로고(빨강, 굵은 이탤릭)에서만 냅니다.

| 역할 | 값 | 어디에 |
|---|---|---|
| 바탕 | 흰색 `#ffffff`, 옅은 바탕 `#f8fafc` (`--color-surface-alt`) | 페이지, 번갈아 쓰는 구간, 표 줄 강조, 미리보기 |
| 중립(남색 계열) | 글자·버튼·어두운 구간 `#0f172a`, 보조 글자 `#64748b`, 구분선 `#e2e8f0`, 입력칸 테두리 `#8b98ab` | 거의 모든 곳. 링크·포커스·선택된 탭도 이 색에 밑줄·굵기로 표시 |
| 빨강 | `#e5121b` (`--color-brand`), 어두운 바탕에서는 `#ff3b42` | 로고와 추천 결과만 = **답** |
| 앰버 | 글자 `#b45309`, 바탕 `#fef3c7` | 경고, staleness 초과, 빠진 필드, 읽지 못한 줄 = **주의** |
| 초록 | `#15803d`, 바탕 `#e8f5ec` | 완료 상태 표시(배지)만 |
| 오류 | `#b91c1c`, 바탕 `#fef2f2` (`--color-danger*`) | 파싱 실패, 요청 실패, 삭제 버튼. **항상 아이콘·문장·바탕과 함께** |

- 화면에서 눈에 띄는 색은 "빨강 = 답", "앰버 = 주의" 두 가지가 되게 합니다. 파랑 같은 별도 강조색은 쓰지 않습니다.
- 오류 빨강은 브랜드 빨강과 비슷해서 색만으로 구분하지 않습니다. 경고 아이콘과 이유 문장, 옅은 바탕을 같이 씁니다.
- 단계 번호, hit 같은 이벤트, 선택 상태는 회색·남색과 굵기로 표시합니다.
- 상태 배지는 글자색과 옅은 바탕을 짝으로 쓰고 항상 글자를 함께 씁니다.
- 어두운 구간의 그래프 선은 `#e2e8f0`, 보조 글자는 `#94a3b8`입니다. 기준 초과 구간은 빗금 + 앰버 라벨입니다.
- `#d97706`은 흰 바탕에서 대비가 3.2:1이라 글자에 쓰지 않습니다.
- 그라데이션과 장식용 그림자, 장식 그림은 쓰지 않습니다. 로그인 화면 오른쪽에도 장식 대신 결과 예시를 둡니다.

## 글자

| 용도 | 글꼴 | 크기 |
|---|---|---|
| 본문 | 산세리프 | 16px |
| 보조 | 산세리프, 회색 | 14px |
| 데이터 | 모노 | 13~14px |
| 화면 제목 | 산세리프 600 | 26px |

- 경로, 패턴, JSON은 항상 모노로 씁니다.
- 숫자 열은 오른쪽으로 정렬하고 `font-variant-numeric: tabular-nums`를 씁니다.
- 굵은 이탤릭은 로고 글자에만 씁니다.

## 레이아웃

- 카드 상자를 늘어놓지 않습니다. 목록과 단계는 구분선으로 나눕니다.
- 장식용 아이콘은 쓰지 않습니다. 아이콘은 사이드바 메뉴처럼 기능이 있는 곳에만 쓰고, `components/Icon.tsx`의 선 아이콘만 씁니다.
- 같은 버튼과 문구를 한 화면에서 반복하지 않습니다.

## 공통 부품

- **탭** (`components/Tabs.tsx`): 글자와 밑줄만 씁니다. 선택된 탭은 남색 글자와 밑줄입니다. 화살표·Home·End로 옮깁니다.
- **코드 블록** (`components/CodeBlock.tsx`): 남색 바탕, 오른쪽 위 복사 버튼.
- **알림** (`features/toast`): 오른쪽 아래 남색 띠(완료는 초록 점, 경고는 앰버 점), 5초 뒤 사라짐. 방금 한 작업의 결과(업로드 처리 끝)에만 씁니다. 화면에 이미 보이는 오류를 알림으로 또 띄우지 않습니다.
- **불러오는 중**: 표는 `SkeletonRows`로 빈 줄을 보여 줍니다.
- **위치 표시**: `프로젝트 / 프로젝트 이름 / 하위 화면`. 맨 끝은 링크가 아닙니다.
- **프로젝트 워크스페이스**: 사이드바 메뉴 개요 · 로그 · 정책 · 분석 · 설정. 정책·분석은 API가 생기기 전까지 "준비 중"으로 둡니다.
  - 개요: 로그가 없으면 숫자 대신 3단계 시작 안내. 로그가 있으면 "다음 할 일" 한 줄 + 요약 숫자 한 줄(상자 없이 세로 구분선) + 최근 업로드 표.
  - 설정: 프로젝트 이름을 그대로 입력해야 삭제 버튼이 켜집니다.
- **요약 숫자**: 28px / 600. 분석이 없는 값은 0으로 채우지 않고 아예 보여 주지 않습니다.
- **분석 결과 문구**: 확정 대신 추정임을 드러냅니다. "예상 히트율", "관측된 변경 주기"처럼 씁니다.
- **목록**: 카드 대신 표를 씁니다. 검색·정렬은 표 위에 둡니다.

## 앞으로 만들 화면 (메모)

분석 API가 생기면 아래 구조로 만듭니다.

- **프로젝트 상세**
  - 위쪽: 프로젝트 이름, 마지막 분석 시각, [분석 실행] 버튼. 파싱 중이거나 로그가 없으면 버튼을 끄고 이유를 보여 줍니다.
  - 탭: 결과 | 로그 | 정책
  - 결과가 없을 때: 탭 대신 단계를 보여 줍니다. ① 로그 업로드 → ② 정책 설정(선택) → ③ 분석 실행
  - 분석 뒤에 로그나 정책이 바뀌었으면 앰버 배너를 띄웁니다. "설정이 바뀌었어요. 다시 분석하세요"
- **정책 탭**: 표로 바로 편집합니다. 열은 패턴(모노), 허용 staleness(초), 매칭 요청 수, 자동/커스텀, 삭제입니다. 패턴마다 매칭되는 예시 경로 3개를 보여 줍니다.
- **결과**
  - 요약 숫자 4개: 엔드포인트 수, 캐시 추천 수, 전체 예상 히트율, 데이터 부족 수. 분석 기간과 총 요청 수도 함께 보여 줍니다.
  - 엔드포인트 표
    - 열: 엔드포인트, 판정, 추천 TTL, 예상 히트율(작은 막대), 오래된 응답, 요청 수, 쓰기 비율
    - 기본 정렬은 요청 수 내림차순입니다.
    - 추천 TTL 숫자만 빨강으로 씁니다. 초와 사람이 읽는 단위를 함께 씁니다.
  - 행을 누르면 오른쪽 서랍이 열립니다.
    - TTL별 곡선: 소개 화면 차트와 같은 형태이고, 추천 점만 빨강입니다.
    - 판정 이유 한 줄
    - 설정 복사: Redis `EXPIRE`, Spring `RedisCacheConfiguration.entryTtl`, `Cache-Control: max-age`
- **프로젝트 목록**: 분석 API가 생기면 엔드포인트 수, 예상 히트율, 마지막 분석 시각 열과 "최근 분석순" 정렬을 더합니다.
- **소개 화면**: 샘플 로그(B12)와 분석(B9~B11)이 생기면 "샘플 로그로 체험"과, 샘플 로그로 실제 계산한 Before/After("전부 60초" 대 추천)를 넣습니다.
